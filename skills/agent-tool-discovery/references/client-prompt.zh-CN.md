# Agent 工具发现与修复：完整中文提示词

复制下面的代码块到具备本机访问能力的 Agent 中。默认授权范围内的可逆修复；只想检查时，在发送时明确写“仅审计，不修改”。

```text
请检查并修复这台电脑上不同 AI Agent 对已有工具的发现和接入问题，让适合共享的 Skills、MCP、CLI 能够被找到并调用。

我授权必要的只读检查和可逆修复。保留现有配置，不额外安装管理软件、运行时或依赖，不升级工具，不删除原文件，不自动启用已禁用资源、扩大权限，或把项目私有资源改成全局资源。普通细节自行决定；需要登录、解决内容冲突或超出范围时再问我，其他可完成的部分继续处理。

一、盘点实际环境与 Agent

确认操作系统、当前用户、执行环境、已安装 Agent 的版本及配置作用域。区分桌面应用、CLI、IDE 插件、云端和容器；遗留目录不代表已安装，本机路径也不代表当前环境能够访问。

优先检查以下产品及其桌面、CLI、IDE 插件和国内外版本：

海外及开源生态：
Codex、Claude Code、Gemini CLI、Google Antigravity、Cursor、Windsurf、GitHub Copilot、OpenCode、Cline、Roo Code、Grok Build、Kilo Code、Continue、Aider、Goose、OpenHands、OpenClaw、Hermes Agent。

中国厂商：
- 小米：MiMo Code；
- 智谱：ZCode；
- MiniMax：MiniMax Code／mcode；
- 字节：TRAE／TraeCode、TraeCode CLI、TRAE SOLO；
- 阿里：Qwen Code、Qoder／Qoder CN、Qoder CLI、QoderWork／QoderWork CN、通义灵码／Lingma IDE；
- 百度：文心快码／Baidu Comate、Comate CLI；
- 腾讯：CodeBuddy、CodeBuddy Code、WorkBuddy；
- 月之暗面：Kimi Code；
- 其他：iFlow CLI，以及实际检测到的其他 Agent。

这份清单是检查线索，不是完整名单，也不是要求安装的软件列表。结合应用、可执行文件、包管理器、IDE 扩展及相关配置，补查清单之外的产品。未知名称先核实身份，不擅自猜测。新旧名称可能属于同一产品，确认后去重。

区分 Agent 客户端与它连接的模型：发现 MiMo、GLM、Qwen、DeepSeek 等模型名称或 API 配置，不代表安装了对应的独立 Agent。

盘点已有 Skills、MCP 和相关 CLI。依据当前版本帮助或官方文档确认实际加载入口、配置优先级和支持能力；不能因为某产品出现在清单中，就假定它支持 Skills、MCP 或软链接。不为未安装的软件创建配置。

只检查相关目录，不扫描整块磁盘，不输出密钥、Token 或登录凭证。若当前环境没有本机访问能力，如实说明，不虚构检查结果。

二、修复 Skills 发现机制

优先沿用现有中央仓库；没有时，适合共享的用户技能默认使用 ~/.agents/skills/。AGENTS.md 是规则文件，不是技能目录。

保留完整技能包，包括 SKILL.md、脚本、资源和引用文件；检查客户端专属语法、依赖和绝对路径。格式相同不代表运行行为完全兼容。

根据实际支持情况处理：
- 原生读取中央目录的 Agent，不重复建立入口。
- 确认支持软链接的，逐 Skill 建立入口。
- 不支持软链接的，受控复制并记录来源和内容哈希；再次同步前检查目标是否被修改。

不整体替换 Skills 根目录，不搬动内置、插件管理或项目私有技能。比较完整技能包；同名不同内容保留并报告，不按修改时间自动覆盖。

建立链接前检查真实路径、父目录链接、自指、循环和失效链接。正确入口保持不动，无法确认用途或兼容性的资源保留原状。目录不可访问时报告，不擅自迁移文件。

三、修复 MCP 和 CLI 接入

MCP：
按各客户端格式，增量补齐适用的用户级共享服务入口，保留原作用域、权限、启用状态和其他配置。不把所有服务无差别注册到所有 Agent。

不软链接整份配置，不复制其他客户端的 OAuth 凭证。同名服务的地址、启动参数或环境变量引用不同，视为冲突，不自动覆盖。

区分已配置、已启用、已登录、已发现工具和调用成功。需要登录时，告诉我具体哪个 Agent、哪个服务需要登录。

CLI：
通常安装一次即可，不重复安装或搬动程序。核对命令名、绝对路径、解释器、运行时、工作目录和必要环境变量名称，检查各 Agent 的实际执行环境，尤其桌面应用与终端的 PATH 差异。

命令名找不到时先查绝对路径；缺少依赖时报告，不擅自安装或修改全局 PATH。

API：
只记录用途、文档、调用入口和凭证引用，不做软链接，也不强行包装成 MCP。

四、建立持久查找规则

在公开仓库和受版本控制目录之外建立本地工具索引，记录名称和别名、用途、位置、调用方法、作用域、接入状态及最近验证结果，不存真实凭证。

在每个 Agent 已确认会加载的用户级规则入口中，以可识别的独立区块加入以下规则，并记录索引绝对路径：

“需要工具时，先查当前会话可用工具，再查统一工具索引，然后核对入口、配置、程序路径、运行环境和连接状态。检查后才能判断缺失，并明确区分未安装、未接入、未启用、未登录、环境不可访问、加载失败和调用失败。”

保留原有专属规则和项目规则。不假定所有 Agent 都读取 AGENTS.md 或支持同一种引用语法。重复执行时更新同一区块，不重复追加。

留下简单、可重复使用的检查和维护方法，说明以后新增 Agent、Skill 或 MCP 时如何补齐入口。

五、验证并交付

修改前在公开仓库之外本地备份，保留原权限，记录本次变更和回滚方法。配置写入采用原子操作，并核对并发修改。日志、差异和报告必须脱敏；没有明确授权，不上传电脑清单、私人路径、配置、报告或备份。

逐 Agent 分别验证：
1. 文件、链接和配置正确；
2. 客户端实际发现或加载目标工具；
3. 最小安全调用成功。

调用前确认不会计费、安装、发送、发布或产生业务写入；无法确认副作用就不运行，标记未验证。文件存在、安装日志、--help 成功或握手成功不能冒充业务调用成功。不通过运行会修改数据的技能来测试它是否可见。

无法访问或启动的客户端如实标记未验证，给出剩余验证步骤。需要登录、重启或刷新会话时告诉我，不擅自关闭应用。

重复执行应幂等：不重复建链接、追加规则或安装已有工具。失败时只恢复本次修改，不覆盖期间其他程序产生的新改动。

最后简洁交付：
- 检测到的 Agent 及实际入口；
- 发现的问题、已修复项和保留项；
- 工具索引位置；
- 逐客户端的发现与调用验证结果；
- 冲突、登录需求和未验证部分；
- 后续维护与本次变更的回滚方法。

六、可选定时任务

完成后询问我是否需要定期自动检查。

只有我明确同意并确定频率后，才核实当前 Agent 的自动任务机制及本机访问能力，再设置任务。已有同类任务时优先更新，避免重复。默认只检查；正常且无变化时保持安静，发现问题或需要操作时通知。

自动修复需要另行明确授权，且仅限上述可逆修复范围；不自动登录、安装、升级、启用禁用资源、扩大共享范围、覆盖冲突或公开诊断信息。

未经我的选择，不创建定时任务。
```
